# Today for AI → RSS (+ doubleAI Research)

Unofficial RSS 2.0 feeds for <https://todayforai.com> and <https://www.doubleai.com/research>, generated by a scheduled GitHub Action from each site's own public machine-readable source. No API key, no scraped layout, no third-party services.

| Feed | What |
| --- | --- |
| `feed.xml` | Latest curated AI intelligence, rolling 24h window (up to 30 items) |
| `hot.xml` | Trending story radar, top 10 by cross-source heat |
| `doubleai.xml` | doubleAI research posts (papers, results, talks), from doubleAI's own `/llms.txt` via `dai_rss.py` |

After the first workflow run:

```
https://raw.githubusercontent.com/<you>/<repo>/main/feed.xml
https://raw.githubusercontent.com/<you>/<repo>/main/hot.xml
https://raw.githubusercontent.com/<you>/<repo>/main/doubleai.xml
```

(or `https://<you>.github.io/<repo>/feed.xml` with Pages + a `FEED_BASE_URL` variable — see below.)

## Setup

1. Push this folder (keep `tfa_rss.py`, `dai_rss.py`, `.github/workflows/feed.yml`).
2. Repo → **Settings → Actions → General → Workflow permissions** → **Read and write**.
3. **Actions** tab → `feed` → **Run workflow**. It commits `feed.xml`, `hot.xml`, `doubleai.xml`, `index.html`, then refreshes every ~20 minutes. Runs that find nothing new commit nothing.

For the nicer `github.io` URL: Settings → **Pages** → Deploy from branch `main` `/ (root)`, and add a variable `FEED_BASE_URL` = `https://<you>.github.io/<repo>`.

## How it works

- `python3 dai_rss.py` fetches doubleAI's `/llms.txt` (one request), parses the `## Research` section, writes `doubleai.xml`. Runs first with `continue-on-error: true`, so a doubleAI outage never blocks the other feeds.
- `python3 tfa_rss.py` pulls todayforai's `/api/v1/agent/latest` + `/hot` (two requests), merges English `title_en`/`summary_en` from `/en/news` by article id (falls back to Chinese if that page changes), writes `feed.xml`, `hot.xml`, `index.html` (which lists the fresh doubleAI count). 3 requests per run total.
- Item `<link>`/`<guid>` point at the original source (publisher URL; doubleAI research page or arXiv URL). todayforai has no per-article pages, except hot-radar stories linking to `todayforai.com/en/story/…`.
- Both scripts are stdlib-only (Python 3.11+), validate XML before writing, and refuse to write an empty feed.

## Tuning

Both scripts accept only `--out DIR` and `--base-url URL` (`FEED_BASE_URL` env as default); the workflow passes neither. todayforai window/category/limit are hardcoded in `tfa_rss.py` (`window=24h&mode=all&limit=30`, hot `limit=10`); the doubleAI section is the `## Research` split in `dai_rss.py`. Schedule: `cron: "7,27,47 * * * *"` (~20 min, staggered off the hour — GitHub's scheduler is best-effort).

Local use:

```bash
python3 dai_rss.py   # doubleai.xml (run first for a fresh index.html count)
python3 tfa_rss.py   # feed.xml, hot.xml, index.html
```

## Optional: TinyFish fallback

If a runner IP gets blocked (403/429), failed requests retry via the TinyFish Fetch API — only with a secret: get a key at <https://agent.tinyfish.ai/api-keys>, add it as repo secret `TINYFISH_API_KEY`. Without it the scripts fail loudly and the old feeds stay live.

Cost is capped: Fetch API only (free tier 1,000 URLs/day), max 4 fetches per script per run, healthy run makes 0, blocked run 1–2. The key is env-only (`X-API-Key` header, never in argv/files/URLs), step-scoped to the two build steps (never the commit step), never follows redirects, and outputs are scrubbed/aborted if the key would appear in them.

## Notes & limits

- `feed.xml` is a rolling 24h window, not an archive; `doubleai.xml` is the full current list from `/llms.txt`. No state file — polling every few hours never misses anything.
- todayforai `pubDate` keeps its `+08:00` offset; doubleAI dates are date-only (UTC midnight). doubleAI credits `doubleAI Team` (the site publishes no individual author).
- Unofficial and unaffiliated; content belongs to todayforai.com, doubleai.com and the linked publishers. Respect their rate limits — don't lower the schedule below a few minutes.
